# Scoped next-message settings

`laplace.writing.session_settings` composes the existing session resolver,
Writing records and project projection specification. It stores no parallel
settings ledger. SDK `session_settings_request`, the native own-session adapters,
`/authoring/session-settings` and `/work/session-preferences` share the protocol.
Follow the issued `settings_read` on a session/turn acknowledgement or the project
preferences read; do not construct another project or conversation target.

A read separates current saved provider/model/effort, recorded per-key origin,
passive catalogue observation, declared/conditional role ceiling and exact
admitted-turn settings. Old per-key origins remain unknown. Project defaults
affect future ordinary conversations; they do not change existing conversations,
dispatched worker/judge defaults or workflow assignment inheritance. Application
model policy stays read-only. Settings never change a role, grant Source/tool
permissions, approve a recipient or launch work. Busy/unknown-owned conversations,
sealed readers and admitted recipient profiles keep their existing ceilings.

A guarded change holds the qualified target, stable `request_id`, settings-only
`expected_basis` and closed authored values. Canonical intent excludes only
`action` and `request_id`; project, target, basis and literal values are included
before alias/effort normalization. Exact replay precedes mutable checks. The
original receipt is historical; `current`/`current_read` is separate. A no-op has
a durable acknowledgement. `NONE` permits only an explicit identical retry;
unavailable or incomplete custody is `UNKNOWN`, never an equality-based ACK.

Explicit withdrawal supplies the exact original change and its intent digest.
The same owner lock chooses either the original recorded effect, without undo,
or durable `NOT_ADMITTED`/`WITHDRAWN` so a delayed original copy cannot apply.
Storage uncertainty remains unknown. Session effects and terminal outcomes live
in existing WSS records; project preferences and their request-history
contribution commit atomically in the existing specification. Legacy writers
preserve this custody. No request history is silently truncated.

A deterministic closed-schema rejection alone carries
`RESPONSE_BOUND_SCHEMA_REJECTION`, `durable:false` and the canonical full-request
hash (including action/request ID). Only its matching direct response can retire
that invalid wire for deliberate editing. It is not a lookup receipt or a generic
HTTP-error escape. Diagnostics contain schema-owned labels, not the submitted
object or unknown credential fields. Null effort means no flag; it is not an
implicit replacement by a tier effort on a model requiring an explicit effort.
