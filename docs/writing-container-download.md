# Download the complete Writing package

The primary download is the workspace ZIP and prebuilt image parts from the private
[repository Releases](https://github.com/phujck/laplace-writing/releases). Repository
read permission is sufficient; separate container-registry access is not required.
No credentials are included.

For a first visit, follow the installation steps below, then read
[Start here](writing-start-here.md) and choose a [task recipe](writing-tasks.md).
Projects is the ordinary entry; project Research is a primary view, and Explore
across projects is in the Workspace menu. Reading
and manual writing need no provider account. The edition details below describe
the currently published package; this guide change alone does not publish a new
source or image cutoff.

**Edition: Writing and development backend.**
[`writing-bundle-20261103-writing-backend`](https://github.com/phujck/laplace-writing/releases/tag/writing-bundle-20261103-writing-backend)
uses local image tag `laplace-writing:writing-backend-20261103`. Use a release only
when all assets and their manifest are actually published; an entry change alone
does not upload them. The prior Workflow operation and Focused review evidence releases remain separate.
Exact source, image and acceptance identities are in the final manifests.

Start with **Projects**, then **Writing**, **Sources** or **Tasks**. **What led
here** opens a task's actual recorded relationships and selected evidence reads;
Home **Recent activity** describes saved events, not current jobs. Conversation **Inspect context**, **Model & settings** and document intake stay
beside the composer; **Options** holds infrequent controls; **Back to reading** and **Show source instead**
keep the editor, retained source and unsent message. Writing keeps the draft in
the editor, also across a reload, until Ctrl-S or **Save changes** writes it;
**Autosave** is a control, off by default; every save warning offers **Keep my
text and save it** first. Send stays explicit. **No verified PDF** does not mean no previous PDF was built.
[Task recipes](writing-tasks.md) explain exact task completion and recovery.

Workflow **Design**, **Runs** and **Guide** retain the same draft and selection.
A workspace design needs an explicit **Use as new draft…** owner choice before
project preparation. Copying a saved body is not complete-lineage transfer. Run
Stop retains its original request before sending and offers only owner-qualified
explicit reconciliation after uncertainty; it does not undo recorded effects.
The [workflow guide](writing-workflow-editor.md) describes supported profiles and
limits. Source21 model HOLD and Source8 unrecorded verdict/absent parent are kept;
external source review and actual browser acceptance have their own records.

**Inspect review evidence** still reads owner counts before explicit bounded
lists/selected routes. Counts do not inspect bodies, and changed consumed inputs
require an explicit fresh summary. The [evidence-navigation guide](writing-evidence-navigation.md)
separates task execution, retained support availability, local acceptance, live
application and publication. Missing earlier scratch raw is not reconstructed.

Current publisher parts/steps, retained Work facts and exact kernel recovery keep
separate identities. Host publication `74970785…` recovered nine selected publisher
parts; its artifacts and reader proof are not shipped. Recipient kernel standing
may remain `UNRESOLVED` and reader support remains `CANDIDATE`. Frozen 22-project,
65-session, three-PDF data and the separate 22-Work metadata keep their earlier
cutoff; this image is not a fresh live Backlog or author-data snapshot. The isolated
operational-memory prototype is outside this delivery.
Open **Explore across projects** from the workspace menu without a manuscript; choose **Project context
(optional)** only to narrow the catalogue. Read exact evidence windows, keep a
native workflow draft beside the bounded relation map, and follow each timeline
lane's recorded order and coverage. The [workspace guide](writing-workspace.md)
and [research workbench guide](writing-research-workbench.md) cover questions,
proposal/review runs, explicit human Apply, registered methods/results and
selected portable handover. Source review plans and the opt-in Source allowance
have their own [scoped authority](development-source-use.md).

Open **Tasks** for catalogue-wide Work search, filters and explicit planning.
Recorded completion and current review are separate; priority, preferred order
and deferral start no task. [Session settings](pilot-session-settings.md) explain
saved future choices and actual admitted settings. [Declared Source inputs](writing-source-inventory.md)
provide bounded code/input pins and honest unresolved kernel standing.

Start in **Sources** with **Add local document**, inspect the retained original,
and choose **Use in conversation** or **Add to Literature**. For passage reviews,
open a project task in **Tasks**, choose **Set up reviews**, then select reviewers
when saving a comment. The [workspace guide](writing-workspace.md) and
[comment-review guide](writing-workflow-editor.md#request-reviews-of-a-passage-comment)
show the steps and recovery controls. Full saved-message reading remains in
**Conversation**; see the [reading guide](writing-conversation-reading.md).

The workspace includes the due-diligence account, Foundations of Synthetics, the Living
System Guide, the mean-force paper and their companion projects, plus SuperARC
and memory campaign code. The [paper collection](writing-paper-collection.md)
and [campaign run instructions](writing-campaigns.md) provide the entry points.
The [entry README](writing-evaluator-readme.md) gives the tour. This edition also
includes the reviewer guide, current project orientation and offline portable test setup.

Open **Workflows** to create, organise and save a definition. For a project-owned
supported slice, **Prepare agent run…** opens a project message; explicit **Send**
prepares its plan/Work. **Prepare start message** then opens the separate Start
request in that same conversation. **Agent runs** leads to recorded step results
and conversations. **Prepare external run…** retains the external/CLI carrier.
See the [workflow guide](writing-workflow-editor.md).

Run inspection now uses the existing graph/list with the exact consumed version.
One existing failed judge can receive an explicit original-parent
[review continuation](failed-review-continuation.md), retaining worker output
and earlier attempts. [Pinned source reads](source-read-contract.md) retain a
refused page until an explicit current-source restart; Material observations and
consumed/adopted revisions stay separate. These capabilities do not establish a
completed paid worker/judge/synthesis cycle.

This edition also includes inspectable selected-action context for the short
continuation request and a [sealed text reader](sealed-text-reader.md). Inspect
the complete input before explicit Start. The reader is one attempt, with exact
result and request recovery; PDF text is not visual reading. Source-host public
canaries qualified that host's exact setup. Its installed proof and evidence are
not shipped: the recipient must separately qualify its provider setup through
the documented local operator entry. Ordinary review remains available.

The image contains the supported Claude 2.1.304 executable and reports reader
support as `CANDIDATE`. Sign in using the [account guide](writing-account-setup.md),
then follow the [local reader qualification procedure](sealed-text-reader.md#local-operator-qualification-attempt).
Reader Start requires the recipient's own judged public canary evidence and
local qualification. Reading conversations and manual editing need no provider.

Application code comes from the installed image, while the mounted workspace owns
project data. The [handover guide](project-data-handover.md) and
[Python SDK example](writing-agent-start.md#hand-over-one-selected-project) show
how to plan, export and inspect one complete selected project into a fresh data
home; they do not require copying the source repository or provider accounts.
This is a matching source/image update over the same frozen 22-project/65-session
private snapshot. Included PDFs and project histories keep their prior scope.
The source/image cutoff is newer than that data snapshot: recipient Backlog
records and planning describe the retained recipient data, not the live author
workspace. Any separately included engineering-programme handover is labelled
as a frozen observation, never installed as live Work or execution approval.

Use the exact assets from the same Release. `container-package.json` records the
image ID, image-part hashes and workspace archive hash. The extracted workspace's
`release/export-manifest.json` and `release/source-manifest.json` record its closure;
`release/current-acceptance.json` records the observed qualification and limitations.
The launch command verifies package identities; it is not scientific validation.

1. Install Docker Desktop (Linux containers) and Python 3.12, or Docker Engine and
   Python 3.12 on Linux.
2. Download `laplace-writing-workspace.zip`, `container-package.json` and **all**
   `container-image.tar.gz.part…` assets from that release into one folder.
3. Extract the workspace ZIP into a new folder. In a terminal in that extracted
   workspace, run:

   ```text
   python scripts/writing_container_package.py start --package "/path/to/downloads"
   ```

   On Windows, `py -3.12` can replace `python`. On macOS/Linux, use `python3` if
   needed. The package path is the folder containing the JSON and image parts.

Open http://127.0.0.1:8771/project?workspace=writing. Read
`release/export-manifest.json` and `release/current-acceptance.json` for the actual
project/source/runtime identities. An unfinished project snapshot need not contain
a finished PDF. Ctrl+C stops the server; your edits remain
in the extracted workspace. AI work requires your own provider login; reading
and manual editing do not. No credentials are shipped.

Included PDFs are preserved release artifacts. Build status after extraction is
unverified until you explicitly build the selected manuscript in this workspace.
Use **Build selected manuscript**, then inspect its actual status and bibliography
coverage. A copied PDF is not evidence that today's sources produced it. This
first build needs no AI provider and does not run merely because you open a page.

GitHub CLI users with repository read access can download this edition's complete
asset set (including the workspace ZIP):

```sh
gh release download writing-bundle-20261103-writing-backend --repo phujck/laplace-writing --dir writing-bundle-20261103-writing-backend
```

Extract that Release's workspace ZIP, then run the launch command above from its
root with the download directory as `--package`. Avoid pairing a newer workspace
with an older runtime and calling it a verified package.

The loader verifies every part before loading, checks the resulting image ID,
and starts the existing Compose service with pulls disabled. It streams parts
without creating another full archive. Parts keep each GitHub asset below its
size limit; all parts are required. Keep enough disk space for the compressed
download and Docker's unpacked runtime (allow at least 15 GB free).

On Linux, the extracted workspace must be writable by image UID/GID 1000; see
the registry guide for hosts with different user IDs.

The image is Linux/amd64; Apple Silicon uses Docker emulation. Provider use needs
network access. After the initial downloads and installation, the included
runtime/projects can be opened without contacting GitHub or the registry.
The existing [account guide](writing-account-setup.md) explains provider login.
The [registry guide](writing-registry.md) remains available for registry-based updates.
