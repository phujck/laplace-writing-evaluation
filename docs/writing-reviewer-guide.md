# A reviewer’s guide to Laplace Writing

Use **laplace-writing** for evaluation. It contains the application source and
selected examples. The larger `laplace` development repository also contains the
author’s long-running research and personal engine history; its wake instructions
are not the startup procedure for this package.

## Current source and Source evidence

The **Writing and development backend** edition carries passage-comment recovery,
retained review/output reading, canonical Help and task recipes. Exact source/image identities and
scoped acceptance are in the manifests; a guide is not a publication receipt. Project data
and the separately labelled 22-Work engineering snapshot retain their earlier
cut. Current-source account v2 is an earlier pinned account, not an independent
review of this source or a refreshed manuscript snapshot.

**Inspect review evidence** reads one Work's owner counts directly from Work or
Backlog. Deliberately list obligations, inspect selected metadata/routes and read
an exact recorded phase. Counts, local satisfaction, currentness, independence,
Source coverage and original-body inspection are different observations. Unmanaged
Work is not a satisfied zero, and zero required obligations is not a percentage.
An old continuation refuses changed consumed input and offers an explicit fresh
summary; the editor's draft/target/pending request is not silently rebased.
See [review evidence](docs/writing-review-evidence.md) for the closed SDK/native/HTTP
contract, response limits and retained row-set guards.

The ordinary Work view and review-evidence inspector use the same checked reader
for a recorded phase body. Follow its issued pages and exact source basis; a
header or count is not the complete body. A stale read can offer fresh inspection,
while unavailable retained bytes stay unavailable. Development status, recorded
acceptance, currentness, adoption, publication and resource disposition remain
separate observations. Source and controller checks have their recorded scope;
they do not establish universal browser or provider behaviour.

## Current task-led interface and evidence chain

Begin with [Start here](docs/writing-start-here.md), then a complete
[task recipe](docs/writing-tasks.md). Projects contain Writing, Sources, Tasks and
Research; a Task is not required for reading or manual writing. Workflows are
reusable recipes, runs are attempts, and reviews are judgements with their own
scope and currentness. **Research** is a project research view; **Explore across
projects** is the optional broader object workspace.

**What led here** follows actual bound task/conversation/result relationships.
Read original replies/files/reviews/runs deliberately, and inspect completion
support availability separately. Missing raw remains unavailable; a direct
receipt hash does not prove all recursively referenced evidence is retained.
Home events and saved conversation history are not proof of current running work.
**Completed — evidence needs rechecking** preserves historical completion; read
the reason rather than treating it as a failed test or unfinished implementation.
Only the offered guarded **Mark done** action records new completion.

Conversation puts **Inspect context**, **Model & settings** and document intake
beside the composer; **Options** keeps infrequent controls. Future-message intent
and preferences are not authority. **Back to reading**
and **Show source instead** preserve the existing editor, source and message.
Writing keeps the draft in the editor (it survives a reload) until Ctrl-S or
**Save changes** writes it; **Autosave** is a control, off by default, and every
save warning offers **Keep my text and save it** first. Send remains explicit. A PDF is separately built;
**No verified PDF** makes no claim about all earlier builds or a new check time.

Accepted application controls, actual browser tasks and installed-container
correspondence are separate evidence. The two ordinary Fable sessions and final
image critique are advisory expert model evidence, not a novice usability study.
The opt-in complete saved-lineage reader and fresh-recipient lineage-v2 transfer
are included, with their explicit budgets and exact original request. Default v1
history/export/restore bounds remain 32 versions/1MB. A new draft body copy is
separate and starts its own history.

The original Source21 model HOLD and the final Source8 unrecorded verdict/absent
parent return are preserved. External source/functional review plus real Root UI
acceptance are separately attributed, not whole-model acceptance. Current release
checks do not claim a fresh useful provider run of a newly saved workflow. See
`release/current-acceptance.json` and the scoped release evidence.

## The idea in one paragraph

The backend gives research objects stable identities and assigns each kind of
object a module responsible for changing it. Human controls and agent tools reach
those same modules. A change checks the caller’s permission and the identity or
revision of the inputs it consumed, updates the authoritative object, and records
the action and outcome. Saved versions and content-addressed evidence retain the
original bytes; readers construct views from these records. Currentness means
that the **specified inputs still match their recorded digests and guards**,
rather than that a timestamp is recent. This makes an edit, result or review
inspectable from its inputs through its accepted outcome. The scope of the
record matters: it does not turn a successful tool call into scientific truth.

## Run the checks

From the repository root, using Python 3.12:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install ./atlas '.[research]' pytest
.venv/bin/python -m pytest tests
node --test tests/project_landing.test.mjs
```

On Windows use `py -3.12` and `.venv\Scripts\python.exe`. The Node command needs
Node 22 and uses its built-in test runner. The Python suite exercises local server
startup, browser assets, project authoring, atomic saves, path/history portability
and container-package guards. Its declared selection is in `pytest.ini`:
`test_writing_portable.py`, `test_writing_portability.py`,
`test_writing_container_package.py` and `test_writing_portable_core.py` (the
consolidated-core conformance witness: a headless Work and saved-source
application with stale refusal and replay, and the existing app on loopback with
a guarded Work write, both run by the selected interpreter against the installed
package). The observed clean Python 3.12 run of this selection is **28 passed**,
from a cold virtual environment holding only the core dependencies and the
`review` extra (that is, `pip install ./atlas '.[review]'`; the `research`
profile shown above was not cold-tested); the entry-page Node run is
**6 passed**. Expected failures in these commands: **none**. This is the portable
evaluator suite, not the full upstream engine regression suite or a scientific
benchmark.

Other test sources retain their original paths because earlier reviews cite their
exact bytes. They are historical review inputs, outside the declared portable
suite. Running one explicitly may need upstream fixtures: for example
`test_literature_support_qualification.py` needs `test_literature_joined_workflow`;
`test_proposal_navigation.py` needs `test_proposal_lifecycle`;
`test_provider_update_join.py` needs `test_authoring_core`;
`test_work_review_repair3.py` needs `test_work_review_lifecycle`; and
`test_writing_dispatch_return_validity.py` needs `work_read_helpers`.
`test_native_writing.py` also concerns the upstream managed desktop/runtime wrapper.
Do not interpret these incomplete source snapshots as runnable package tests.
Their original failures remain in the retained reports; no failing assertion has
been rewritten or marked expected-to-fail to obtain the portable result.

If a package will not start at all, the read-only inspector runs without the
kernel and names what is declared, what changed and what the recovery route is;
its trust boundary and the reimport and currentness routes are in
[writing-recovery-and-currentness.md](docs/writing-recovery-and-currentness.md).

## Vocabulary in the code

- **Owner:** the module responsible for a particular object’s state and writes.
- **Door:** a public operation or endpoint leading to an owner.
- **Bank:** save a typed record or evidence body for subsequent inspection.
- **Custody:** retaining and resolving the exact bytes named by a record.
- **Witness:** recorded observations supporting one identity/currentness check.
- **Seam:** an interface between modules or stages.
- **Fold:** derive a view by reducing stored records or their structure.
- **Upfold:** construct a coarser representation; ordinary app startup does not run the engine’s semantic upfold.
- **Conceptric:** the design pattern of an addressed container with content, state, metadata and typed relations; concrete owners implement it for their objects.
- **Projection:** a derived reading/presentation of authoritative data.
- **Guard:** the expected identity/revision that a mutating operation must check.
- **Receipt:** a record of an attempted operation, its outcome and relevant basis.
- **Currentness:** whether the selected dependency basis still matches.
- **Eigen:** the name used for the agent working through this system.
- **Astra / Sol / Opus / Fable:** model names or recorded aliases, not architectural components.

## What currently stands—and what was corrected

Three claims you can inspect are: **human and agent operations share backend
owners** ([tool entry](src/laplace/native/tools.py),
[HTTP adapters](src/laplace/web/authoring_http.py)); **changes and reviews carry
an explicit consumed basis** ([source application](src/laplace/manuscript/source_application.py),
[review owner](src/laplace/work/project_work_review.py)); and **the supplied workspace
has independently checked source/entry behaviour and portable local checks**
([prior entry acceptance](release/source-orientation-acceptance.json),
[original package acceptance](release/acceptance.json)). These have bounded scopes;
they do not assert every upstream test or future SDK feature is complete.

This edition also exposes managed code/data homes, scoped native workflow
Save/Prepare, app run/step/public-result inspection and complete selected-project
handover through existing owners. Their source and synthetic native checks are
separate from installed-image checks. Real app use reached preparation/launch and
worker publication, but a full paid independent-judgement/parent-synthesis cycle
remains unobserved. Follow [agent startup](docs/writing-agent-start.md) for actual
SDK/CLI routes; imported public sessions cannot resume the original provider.


Three earlier candidate conclusions failed their checks: complete re-export history
was not established when 1,274 bank rows and 14 associated act rows were omitted;
a review could appear current against unrelated/partial input pins; and a retained
Work draft could acquire a newly inspected guard without explicit adoption.
The corresponding source fixes and subsequent checks are retained in the
[correction index](release/reviewer-evidence/corrections.json).

Withdrawals are preserved deliberately. They disable an earlier conclusion without
erasing the attempt that produced it. `NOT_PERFORMED` describes a check that was
not run; `UNPROVED` describes an obligation lacking sufficient evidence; neither
means every part of the system failed. A current failure remains a failure. Read
the final disposition, its exact source/input scope and the matching checks.
The audit trail makes those decisions inspectable; it is not a substitute for
assessing whether the implementation or scientific argument is sound.

## Why the documents are here

Start with **Foundations of Synthetics**, **Due Diligence** and the **Living System
Guide**, as linked in the [entry README](README.md). They provide the theoretical
motivation, the case for the prototypes, and the system’s operational explanation.
Supporting physics papers and numerical campaigns are examples produced and
reviewed through the workflow. They are optional demonstrations for a software
reviewer; the five-file code route above is sufficient to begin assessment.
