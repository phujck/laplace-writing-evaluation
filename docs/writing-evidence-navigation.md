# Task outcomes and supporting evidence

Open **Tasks**, choose a task and read **What led here**. Its purpose, current
state and next action remain separate from the history of what happened.
Documents and sources can also be read without a Task.

Follow offered **Read reply**, **Open conversation**, **Read file**, **Read review**,
**Read Source basis** or **Read run** links deliberately. The list identifies recorded relationships; it does not
mean those bodies have been read. Continue through offered pages, or explicitly
restart when a selected observation has changed. Returning from a reading keeps
the selected Task and any later draft or pending request separate.

An actual task-bound conversation differs from associated external evidence.
Old sessions without a task binding remain unbound; titles or similar text do
not create a relationship. An unavailable exact reply stays unavailable even
when its summary can be read. A corrected current reading is offered separately
from an old malformed link. Artifact identity includes its recorded project,
scope, path, ID and revision; the reader does not try another scope after a
refusal.

**Recent activity** names the event, its date and its destination. Finished
conversations can remain readable when no job is running. In-progress is a saved
declaration; Running requires a current execution observation. Neither an old
task completion nor the absence of a live observation proves that work is
running or never ran.

## Completion and availability are different

Use **Update task status** to distinguish the current saved record from a new
disposition. **Mark done** is available only under the task's actual conditions.
Required reviews, prerequisites and evidence must satisfy their declared basis;
saving a workflow, handing off a reply or recording synthesis does not complete
the task automatically. Reviewer approval is permission, not an accepted review.

**Choose saved evidence** selects admitted project items or run outputs.
An offered declared Writing file is a file choice, not an Artifact receipt or
proof that its contents were checked. The chooser does not read every source.
Advanced exact paths remain inspectable. An optional retained-support declaration
names a pinned artifact manifest and its selected retained items. Essential
outputs belong in their existing persistent Artifact or Run custody before
completion; disposable scratch cannot satisfy required retained support.
Existing resource refusals and partial coverage remain visible.

Historical Done remains a recorded achievement. Current review may be required
because the consumed scope or evidence changed. Unknown is not a failed test.
Supporting evidence can be unavailable while directly named completion records
still match; old tasks may have no supporting declaration. Missing raw is not
reconstructed by a summary or by rerunning an experiment. No old completion or
review is silently renewed.

## Source, live app and published edition

A reviewed local candidate, the source adopted by the running app, and a
published distribution are different outcomes. Open the offered integration or
release records and their dates. A model reply or completion count proves none
of these joins. The recipient data cutoff can be older than its application
source; a source upgrade does not automatically carry current conversations,
tasks, accounts or host qualification.

## Existing read and custody owners

The opt-in project Work read uses `view: provenance` and a closed request with
`demand: aggregate`, `relationships` or `evidence` or `choices`. Pagination uses owner-issued
offset, limit and observation inputs. The local SDK follows the issued project
payload with `work_read`; owner discovery remains a different handle family.
Native callers retain their actual project Scope; a JSON namespace does not
grant workspace authority. HTTP and SDK have their own actual admission.

Optional `completion_support` names an existing artifact by exact ID or scoped
path plus expected SHA256. Its typed `laplace.work-evidence-support/1` content
qualifies the selected Work, scope revision and retained/disposable items.
Selected artifact and run owners validate their own references. This is not a
new ledger, generic arbitrary-path reader or recursive scan of report strings.
The detailed request contract is derived from the actual Work owner.
