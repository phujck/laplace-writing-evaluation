## Callable stages and profiles

The native writing operation is `writing_stage`. With an empty payload it returns
the compact catalogue. For example:

```json
{"stage":"voice_integration"}
```

The selected stage returns its instructions, selected source identity, relevant
profile identity/content, precise material-read routes, execution operations and
completion criteria. `view` selects `summary`, `guidance` (also `full`) or `materials`. Supplying
the previous `known_revision` returns a short unchanged handle instead of another
copy of the instructions. Omitting it requests the body again. Current stages are:

- `scientific_integration`: read the connected manuscript, evidence and argument,
  then apply substantive corrections.
- `voice_integration`: read the selected author profile and original passages,
  apply the pass, then judge the actual changed prose and rendered pages.
- `presentation`: title/byline, cover, document style, scientific visuals and
  exported artifact inspection.
- `build_acceptance`, `engine_acceptance`, `ui_acceptance`, `provider_context`:
  expose the relevant part of the existing workspace acceptance profile.

Repository/engine sessions with shell capabilities call that same owner directly:

```sh
python -m laplace.writing.stages PROJECT --repo-root . --stage engine_acceptance
```

Omit `--stage` to discover the catalogue. `--repo-root`, `--view` and
`--known-revision` make checkout binding and bounded reentry explicit. This does
not make a manuscript session's unavailable host tools available: role capability
and a stage's instructions are separate contracts.

The stage composes existing operations. `writing_style` reads the profile and
provenance; `writing_style_calibration` reads recorded original passages;
`writing_style_change` changes project selection/genre/guidance;
`writing_style_profile_change` edits shared profile content with provenance.
`apply_revision`, the scientific owners, `build`, `build_status` and `export_pdf`
perform their existing actions. `help` supplies the exact current payload for each
operation. `document` reads presentation state; `source` reads manuscript prose.

Stage preparation is not completion. The applying session and subsequent reader
must record actual read coverage, applications, checks and gaps. Host-level engine
probes and browser interaction require those capabilities: a writing session
without them must identify that gap, not substitute a fabricated result.

The engine acceptance profile's historical benchmark samples are retained in its
source file. They are omitted from ordinary stage guidance and must not be passed
off as current measurements. No extra profile text or full history is injected on
every turn just because the files remain available.
