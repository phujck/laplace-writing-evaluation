# Selected Source meaning and kernel recovery

Source discovery, retained meaning, current review and published kernel knowledge
are separate observations. An architectural owner label is not a kernel node ID.

An existing Source-contract inspection offers `source_kernel_read`. Its publication
list contains only explicit in-scope Work handoffs for the declared
`kernel.declared-source` consumer. Choose the issued read; no body, Work identity,
node ID or authority is supplied by the browser. A new source-scope Work obligation
binds the actual owner, operation, consumer and selected segments. The ordinary
handoff retains those exact segment bodies and a bounded kernel context containing
their declared purpose, relations, authority and recovery. Old handoffs are not
backfilled; their ordinary retained-version reads remain available.

Preparation verifies the selected handoff, exact eligible handed raw-source pins,
retained bodies and bases. The declaring module must itself be pinned; its handed pin must match the disk edition recorded by the publisher. Qualified
Source handoffs resolve their original configured checkout and base; they never
fall back to equally named canonical files. Current disk pins still do not attest
loaded Python code. Review counts and latest acknowledgements are excluded from
the semantic fact content.

Each logical `OP-SOURCE-…` identity is a full canonical digest of the qualified
repository, unversioned Source-contract identity and segment. The content handle
separately binds exact facts, typed relations and source pins. Equal inputs can
share a leaf while every selected custody receipt remains recorded; conflicting
editions for one leaf in a cut refuse. This is a derived identity, not proof that
a node is in a published kernel.

The selected `retained_read` serves only that segment. The issued current-standing
read delegates to the canonical review owner and retains the selection's scope.
An explicit counterpart read verifies the active publication receipt, artifact hashes
and exact selected node/content/semantic identity. Missing or mismatched evidence
is `UNRESOLVED`. Preparation, a file shard, a passing check or an inventory count
is never publication or acceptance.

## Supported selected publication

The trusted workspace SDK `source_publication(payload, root=...)` and existing
operator `scripts/laplace-python scripts/reembed.py --source-publication REQUEST.json`
use the same closed owner. An explicit `LAPLACE_REEMBED_ROOT` selects an isolated
publication root; the selected system interpreter/device policy still applies.
Native/project calls cannot publish. A read capability is not an execution grant.

1. `prepare` accepts only explicit versioned Source-contract references, canonical
   namespace/Work/handoff/obligation coordinates and selected segment names in
   `inputs`. It returns the owner-issued `prepared` packet and
   `expected_publication_basis`. It publishes nothing.
2. `commit` takes those exact values and a stable `request_id`. Current source,
   retained context and parent artifact pins are revalidated under the same
   exclusion as ordinary full publication. Caller leaf bodies are never accepted.
3. `request` with the original ID reports `RECORDED`, terminal `REJECTED`, nonterminal
   `NONE`, or `UNKNOWN`. Replaying the same completed commit returns its original
   receipt before today's mutable source admission. Changed intent refuses.
4. `recover` with the original ID is explicit. An unresolved live owner is left
   alone. A dead attempt can restore only its journal-bound backup and own partial
   publication; a newer/unrelated artifact change refuses. Missing/corrupt recovery
   evidence remains unresolved. Never replace an uncertain request with a new one.

Timing history is streamed and every JSONL record is validated, including its final
newline. The existing 16 MiB limit applies to one record, not the accumulated
history. Current/request reads retain only the selected receipt or match count;
append and recovery copy/compare the exact historical prefix in bounded blocks.
This still reads the history; it is not an indexed or constant-I/O lookup.

A scoped contribution preserves unrelated retained nodes, authority and embeddings.
Its receipt declares selected leaves, affected ancestors/index/vector-cache changes,
exact resulting artifact hashes, parent/retained bases and selected custody. The
retained metric and semantic sidecar keep their old basis; no metric refit, global
currentness or complete-world capture is claimed. No authored sew-up close receipt
is fabricated or replaced. Local established GPU embedding is required, with no
silent CPU fallback or provider invocation.

The bounded `engine.source_kernel_input` adapter reads the current receipt's
selection packet. The next ordinary full publisher revalidates/reconsumes it through
Keeper's existing `semantic_input_frame`/`build_self`; absent new selection never
means a broad Source capture. Verified historical coverage reuse remains historical.
The active Source counterpart has one `current-publication-object` typed recovery
route. It verifies actual caller Scope, active publication/artifact identity and
exact retained node/content, independently of today's raw Source pins. Thus an edit
can stale fresh preparation while the previous published facts stay readable on
their own basis. Older unavailable publication bytes refuse explicitly, never
substitute today's tree. Unrelated historical side-ref readers retain their own
history semantics; retired F is not current Source publication proof.

The original `source-contract` descent still reads exact retained canonical meaning
through actual supplied Scope, not fuzzy names or a JSON scope override. Writing
body references are not global Atlas custody handles. Reads never launch a publisher.

A useful actual Source change still requires its human Work grant, exact candidate,
isolated fixed-input check, independent qualified review, original-parent synthesis
and Root adoption. Source-only native-call allowances are not workflow limits.
Authored close/upfold and independently verified recovery remain distinct evidence.

## Historical engine obligations

Backlog offers a separate human/root entry for historical engine work orders and
promises. It uses the existing selected-source `wake.ledger_account` fold, including
resolution evidence and deferred/open/closed semantics. It never converts WO/PRM
identities into namespace Work or guesses relationships, rank, closure or promise
fulfillment. Project-native access refuses before reading or counting a source.

The catalogue scans only the explicitly selected registered source, under its
64 MiB/20,000-row bounds, and returns bounded metadata with cut and malformed/partial
coverage. It is not constant-I/O, a global body index or an audit of the historical
programme. Explicit exact record reads carry a raw pin and bounded continuation.
Planning drafts, pending requests and current canonical Work remain separate.

## The publication operation describes itself

`domain.representation:source_publication` is an owner-authored Source contract for
the existing publisher. Its nine parts explain purpose, admission, selected inputs,
composition, interruption recovery, authority, currentness, exact descent and bounds.
They do not describe every kernel operation or certify loaded Python code. The same
Source chooser and owner-issued current-part/step reads inspect it. A current read
keeps its observed declaration version; if that changes, re-inspect rather than
substituting a new answer for the old observation. An observed current digest is
not yet an addressable retained version.
