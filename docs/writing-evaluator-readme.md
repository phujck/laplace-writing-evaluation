# Laplace Writing — inspectable research workspace

Laplace Writing brings manuscripts, supporting material, work and history into
one inspectable research workspace. Browser controls and agent interfaces use
the same owners, so you can follow a result back to its sources, changes and
recorded evidence.

## Writing and development backend — 3 November 2026

Write and comment on a passage, reopen a saved comment, request an approved
review or writing proposal, and inspect the result before applying it. Passage
comments retain the exact source, including TeX and mathematics. Unsupported
selections offer an explicit supported target; your unsent text is retained.
Request recovery distinguishes saved results, uncertain requests and conflicting
local copies. **Check** inspects the original request; it does not send it again.

Tasks expose the recorded review and its full retained body through bounded
reads. Development work can prepare its complete source handoff, inspect check
output and record the review-and-parent-return plan before dispatch. Accepted
work, current source, the running app, publication and resource cleanup have
separate recorded states.

Use [task recipes](docs/writing-tasks.md) and
[the development guide](docs/development-source-use.md) for these paths.
The matched package and its exact acceptance limits are recorded in
`release/current-acceptance.json` and the package manifests. The examples retain
their earlier frozen data; this release does not refresh private research or
claim whole-kernel embedding coverage.

## Workflow operation edition — 30 October 2026

## Follow a task to its outcome

Open a task and **What led here** to read its recorded history, then choose an
offered reply, conversation, file, review, Source basis or run. Supporting evidence
and current availability are separate inspections. The app does not reconstruct
missing scratch files or infer a native conversation from an external report.
**Home** shows bounded recorded events and destinations; **All activity** opens
the fuller recorded history. Neither is a running-job counter.

A completed task can need evidence rechecking without becoming unfinished work.
Read its actual reason and offered next action. **Update task status** → **Mark
done** → **Save task status** is offered only when current prerequisites, required
reviews and evidence permit it. A reply, handoff or synthesis does not close a
task automatically. Local acceptance, live application and distributed release
need their own records. See [the task recipes](docs/writing-tasks.md) and
[exact evidence navigation](docs/writing-evidence-navigation.md).

Conversation keeps **Inspect context**, **Model & settings** and local document
intake beside the composer. **Options** holds infrequent controls. Its retained
reading, target, future-message intent and explicit **Send** remain separate. **Back to reading** returns to your place;
**Show source instead** switches to the same retained source when the editor has
too little room for both. Writing keeps your draft in the editor, also across a
reload, until Ctrl-S or **Save changes** writes it; **Autosave** is a control,
off by default, and every save warning offers **Keep my text and save it** first.
PDF builds remain separate and explicit. **No verified PDF** does not establish that no PDF was ever built.

The current source/image edition and frozen data have different cutoffs. The
package retains the same 22 projects, 65 sessions, three roadmap PDFs and earlier
22-Work/50-file metadata projection from private `3b7607ca`. It is not a new copy of
the live author's tasks or design sessions. Recipient reader support remains
`CANDIDATE`, without host proof. Exact identities and scoped acceptance are in
`release/current-acceptance.json` and the package manifests.

## From a source to a review

1. In **Sources**, choose **Add local document**, select a PDF or UTF-8 document,
   then **Add document**. Inspect its text or original page. **Use in conversation**
   selects that reading beside your message; **Send** remains explicit.
2. Choose **Add to Literature** for a retained original, enter its **Title** and
   **Source provenance**, then **Save to Literature**. **Read source** opens the
   saved source; **Link to claim** uses an inspected passage and claim. Asking a
   question does not require a bibliography.
3. For agent reviews, open an existing project task in **Tasks** and choose
   **Set up reviews**. Enter each question and its required **Review scope**,
   then **Save review questions**. Reviewer approvals are optional and separate. On the passage comment, open **Reviewers and limits**,
   select reviewers, then **Preview reviews** to inspect the limits before
   **Save and request reviews**. You can also save the comment alone.
4. Read **Review responses** together, including partial responses, and inspect
   the task's progress and next action in **Tasks**. Recovery is explicit; a
   review verdict does not apply a manuscript edit or complete the task.

The [workspace guide](docs/writing-workspace.md) covers document reading,
Literature, lost responses and safe returns to your draft. The
[comment-review guide](docs/writing-workflow-editor.md#request-reviews-of-a-passage-comment)
and [Work review guide](docs/writing-work-review-lifecycle.md) explain setup,
approvals and follow-through. **Help** describes the controls in the current view.

Complete saved requests and public replies remain readable in **Conversation**;
use **Continue reading** for a long message. Your unsent message stays separate.
See the [conversation-reading guide](docs/writing-conversation-reading.md).
Reusable workflows, recorded runs and selected-project handover remain available.

## Workflows, run inspection and project handover

1. Open the [matching workspace and image package](docs/writing-container-download.md),
   then visit `http://127.0.0.1:8771/project?workspace=writing&app=workflows`.
   You can also choose **Workflows** in the workspace navigation.
2. Choose **New workflow**, add steps, and select a step to edit its role,
   instructions and settings. Use **Connect** or **Nest** to organise the graph,
   or **List view** for the compact keyboard-friendly view.
3. Choose **Fit workflow** for an overview and **Center selected** to find the
   selected step. The four **Move** controls also position it from the keyboard.
4. Choose **Save definition** to record a version. **Reinspect current** checks
   for updates; **Compare draft with current** lets you review and explicitly
   adopt a newer save basis while keeping your draft.
5. For a saved project workflow, choose **Prepare agent run…**, select a supported
   builder/reviewer slice, and enter its goal and parallelism bound. **Prepare in
   conversation** opens an exact version-qualified message. Review and **Send** it
   to admit an author turn that prepares the existing dispatch Work and plan.
6. Open **Agent runs** to inspect that saved version. **Prepare start message**
   opens a separate request in the original preparation conversation; only explicit
   **Send** starts it. Select a recorded step for its full public result, saved
   actions, typed return and original conversation, then **Return to workflow**.

An open run uses the same graph/list and inspector in read-only mode. It shows
the exact consumed definition and prepared dependencies, keeping newer saved
versions and your unsaved draft separate. Completed worker output and earlier
review attempts stay available. For one existing settled judge with a missing,
invalid or unreadable return, **Prepare review continuation message** opens its exact request
in the original parent conversation; review and **Send** explicitly. It does not
retry workers or rerun a valid judgement. See [the recovery scope](docs/failed-review-continuation.md).

**Prepare external run…** retains the separate external/CLI carrier with its
source node, goal and write paths. It does not create an app conversation.
The [workflow editor guide](docs/writing-workflow-editor.md) covers exact versions,
full instructions, settings, unsupported slices and draft/uncertain-result recovery.
Reading and manual workflow editing need no provider login.

Source pages can pin the complete raw source with the owner's returned handles.
If a continuation refuses changed bytes, the old page remains an earlier
observation. **Restart source observation** explicitly reads current bytes;
Material shows the new observation while retaining its consumed revision.
Adopting it remains a separate inspected action. The [source-read guide](docs/source-read-contract.md)
explains page/next/restart handles and the raw-source versus selected-value hash.

The workspace's **New workflow** starts with workspace ownership. App runs need
an existing project-owned definition: create it through an admitted project author
using native Save, or through `sdk.workflow_save` with that registered project's
explicit `scope`. SDK Save grants no parent turn or launch authority.

## A short tour

1. **Projects → Home:** open an example and read its purpose, selected manuscript
   and current Work. The top bar's **Workspace** menu reaches Projects, Workspace
   activity, Workspace dependencies and App settings from any view; the navigation
   is fixed on wide screens, compact with short labels at tablet width and a
   **Menu** drawer on narrow screens.
2. **Material:** read a named guide, source or artifact; its **Shared material**
   section holds the project's shared bindings. Every reading opens in the one
   inspector: a nested read replaces the panel and offers **Back to …**, Back on a
   previously read owner shows *Previously inspected · time* with **Read current**,
   and Close at the root returns focus to where you were. Download preserves the
   inspected artifact.
3. **Work:** select a task, read why it is ready, blocked or needs review, then follow
   its prerequisite and evidence links. Historical completion and current acceptance
   are separate; changed evidence needs review, not silent hash renewal.
4. **Logical structure and Research:** inspect a claim's meaning, sources, typed
   relationships, literature passages and linked results. An engineering claim's
   **Open in Logical structure (opens separately)** link reaches its original owner.
   Reading evidence does not acknowledge a new basis or establish scientific validity.
5. **Review & notes and Activity:** inspect exact saved proposals before a decision;
   use **Changes & history** for saved-version comparisons. An exact failed-operation
   record exposes its original arguments and recorded recovery read. Current tool
   help is a separate inspection. Close returns to the launcher.
6. **Manuscript and Figures & output:** read the source and PDF, inspect a figure's
   evidence and build status. Create an unrelated project for an editing rehearsal:
   change a paragraph, inspect changes and Undo, then explicitly build and read its PDF.

included locations while retaining old source identities. Exact recorded artifacts,
current source and freshly built outputs are distinct observations.

In the container, installed code and UI live under `/opt/laplace` and site-packages;
the mounted `/workspace` supplies registry, profiles and writable project data.
The managed host launcher can also select a code root separately from an existing
data root; see [operational homes](docs/operational-homes.md). In that mode,
`source_start` records selected code and `workspace_start` consumed data profiles.
A foreground data-root fingerprint may contain no implementation code. Installed
package/launcher identity, `runtime_start` and the served `frontend_bundle` remain
separate observations.
See the startup guide and `release/current-acceptance.json` for evidence and limitations.
After an application-code change, reinstall/update and deliberately restart the idle
server; manuscript edits through the app do not require a runtime rebuild.

Private calibration originals, unrelated projects, credentials, provider raw
transcripts and personal engine state are excluded. This private evaluation grants
no new public redistribution licence; bundled third-party notices remain attached.

Release builders use explicit project intents; the unfinished study is a current
project snapshot. The [implementation/release guide](docs/writing-evaluation-release.md#release-contents-and-clean-checkout-proof)
gives the exact export command and qualification steps.
