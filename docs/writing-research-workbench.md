# Research workbench

Start from the research workspace without opening a manuscript. Projects are optional lenses over the objects their existing owners expose. Removing a lens keeps the selected object; a source, question, claim, method, result, Work item and workflow definition keep their own identities.

Open an object to read its full purpose, current situation, explicit relationships and available actions. Unavailable coverage is shown as unavailable. A list is not proof that no other work or source exists. Use the existing workflow editor for saved definitions and its graph/list controls; the workbench does not replace that editor.

## Questions, evidence and claims

Choose an existing editable logical-plan context to save a question. Source-optional contexts remain usable for Work, materials and conversation; an absent logical-plan owner does not silently create a manuscript. From the question, save a claim, method or result/evidence note. These are existing canonical concept kinds, not a second research-object store. A note is not a measured Research result or a claim-verification certificate.

Read a retained source through its issued reader. Select the exact observed page or character window as evidence; the reader supplies the input descriptor and complete raw-source pin. Do not hash rendered prose or infer page coordinates. ART/PDF reading uses the existing intake reader; the original file remains separately available. Extracted PDF text does not claim figure/layout understanding. An explicit selected packet contains exactly the admitted representations and windows, with byte/character measurements and coverage.

Use **Record selected consumed inputs** only for inputs the object actually used. The owner validates the retained source identities and records their bases. A bibliography association, semantic support relation, measured-result binding and scientific judgement retain their separate existing owners: consumption alone certifies none of them. Existing Research records and registered producers remain the measured-result and method execution route.

A saved decision retains its original request and exact intent. After a lost response, inspect that original submission or retry its identical wire explicitly. An absent or uncertain read does not authorise a new request. For an unconfirmed creation, explicit settlement either returns the recorded object or durably prevents the old request from creating it. Only then use the issued fresh-decision read, keeping newer prose. Never put current guards onto an uncertain old request.

## Review, consequences and manuscript application

Choose the current manuscript source explicitly before preparing a proposal run. This target choice retains its selection identity and exact selected raw-file pins, separately from the scientific evidence packet; a changed source requires reinspection, not a fresh guard silently put on the old choice.

Saved workflow settings, admitted recipients and actual attempts remain separate. The supported run policy uses an explicit selected evidence packet, proposal writing, independent review and bounded revision, with a human manuscript-application boundary. A document-only reader is separately labelled and follows its own qualified input boundary. Ordinary workflow limits are not development Source grants or the optional Source native-call allowance.

Open the issued dependents read to inspect consequences, then explicitly choose a changed version or scientific assumption. **Mark for reconsideration** records a concern only for a genuinely pinned dependent; **Record author judgement** addresses its canonical concern under the current basis.

Consequences follow recorded consumed bases. Merely related objects are distinguished from dependents, and a pure read creates no flags. A changed scientific assumption needs an appropriate bound judgement or explicit author disposition. A producer saying that bytes stayed equal cannot clear it. Work/run views reference the same canonical concern and preserve negative judgements and unrelated accepted branches.

Conversation uses an explicit **Use** decision for the selected owner context. It does not inject hidden source bodies, overwrite the author's draft or send a message automatically. System objects without an owner-admitted conversation namespace say so rather than inventing a project.

## Selected portable handover

Local inspection and recipient delivery are different views. Choose each included object and explicitly permit sharing; choose private/excluded, unavailable, external or runtime-unbound standing for the rest. An omitted entry carries only a constant omission marker, not its name, path, hash, title or prompt. Local read access does not grant sharing consent.

Preparation retains an ordinary ART manifest. The closure carries explicitly selected local source/artifact bytes, necessary ART/body records, frozen scientific meaning snapshots and selected workflow-definition lineage. Frozen snapshots retain the original scientific subject and basis as provenance; reopening them does not create new live scientific assertions. A configured external repository must first be explicitly retained locally or remain external/unavailable; it is not silently copied.

Export to a fresh local recipient directory under the offered editable file/record/byte budgets. Follow the exact same-destination inspection after an uncertain export: **COMPLETE_MATCH** proves that manifest, **NONE** remains nonterminal and **UNKNOWN** preserves uncertainty. Do not silently choose another destination.

Reopen the recipient through ordinary project, ART/file and workflow-definition owners, with the origin unavailable. Included bytes must match their pins. External links are not fetched automatically; omitted items and unbound runtimes stay explicit. Credentials, provider bindings, host qualification and unrelated history are not transferred. Later origin changes do not change a published frozen closure.
