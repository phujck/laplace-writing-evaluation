# Task recipes

Find your project, do a task, inspect its outcome and return without losing your place.

## Open or create a project

No AI account is needed.

1. Choose Projects. Open a title or Create a project.
2. For writing, enter a title and purpose and choose Article or Book, then Create project. A General project does not automatically offer Writing.
3. On Home choose Writing, Sources or Tasks. If Writing is absent, use Add manuscript only when offered, or choose an Article or Book through Projects.
4. Use the workspace menu for other projects and Activity. Research is the project literature, calculations and proofs; relationships and system tools are optional.

## Read a source and ask a question

Reading needs no AI account; Send needs a provider. Linked material comes first with Read; Manage holds its other controls.

1. Choose Sources, then Add local document. Select a PDF or UTF-8 text file and check its destination.
2. Leave Show this document in Sources checked to add its entry, then Add document. The original is saved; no message is sent.
3. After success, View in Sources. For an unfinished entry, Check project before adding to Sources, then Add saved original to Sources when offered; do not upload a duplicate.
4. Choose Inspect document text or Inspect PDF text. Read the shown passage/page and coverage, then Use in conversation to select it.
5. Before Send, use Inspect context beside the destination to check the reading. Next message sets future intent, not permission. An inspected window is not the whole document.
6. A file's Prepare a question about this file fills an unsent question; a filename alone is not inspected text.
7. Find literature or Add to Literature keeps that claim or passage as the target; a link is not support.

## Write and return to saved text

Manual writing needs no AI account. A document may be an authored draft even when every edit is saved.

1. Choose Writing or Continue writing in a writing-enabled project. Otherwise see Open or create a project.
2. Click a paragraph to write. Ctrl-S or Save changes writes it; until then the draft stays in the editor, even across a reload. Autosave is off by default.
3. Sources beside writing opens a saved source without replacing the editor. Inspect its coverage; browsing does not replace the message target.
4. Change source opens choices; Close sources closes the pane. Back to writing and Return to source keep both places.
5. On a narrow screen an open Conversation fills the pane: Back to reading returns to the text, and Show source instead opens the source there.
6. Leave and reopen Writing to check saved text. Each save warning offers Keep my text and save it first.
7. PDF is built separately. No verified PDF means no verified build is available, not that none was built. Build stays explicit in Document tools, with Undo, Redo, Drafts and Document setup.

## Organise tasks and reviews

Planning a task does not start it. Review questions can be saved without approving an AI reviewer.

1. Choose Tasks. Open a purpose, state, reason and next action. Add task creates a goal with a completion condition.
2. Plan this task sets priority, order or deferral when offered. Saving records intention, not execution or approval.
3. Set up reviews: enter questions and each required Review scope, then Save review questions.
4. Optional reviewer approvals: inspect scope/duration before Save questions and selected approvals. This does not start a review.
5. Now names who is acting and the one turn a Stop would touch; Next lists the owner's permitted actions by kind: a form here, an owner-issued template shown as issued, or an inspect-only read. Ready or proof arrival is not acceptance or permission to mark done.

## Revise a passage from a comment

A comment, proposal, applied change, build and your decision are separate records; the Revision chain shows which exist.

1. Right-click a paragraph, choose Comment on this passage and Save comment; math or code is never split. Unsent drafts await your choice. If the reply is lost, Check save keeps your text and posts nothing twice.
2. Ask for a revision in Conversation or request an offered review; responses show each reply and change no text.
3. Open a proposal with Review in manuscript and compare it with the current passage; if it changed, re-read rather than retry.
4. Apply only edits you accept; applied text is a source change, not accepted science.
5. Build, read the PDF, then record your decision and its evidence on the task.

## Find what happened and where the result went

A Task can link conversations, sources and reviews; sources and documents also work without one.

1. Choose Tasks, open the task and What led here. Read its purpose, latest outcome and event dates.
2. Follow offered Read reply, Open conversation, Read file, Read review, Read Source basis or Read run links. History metadata is not body inspection; pages and changed-input restarts stay explicit.
3. A bound conversation belongs to this Task. Associated evidence is not native execution; a summary is not an unavailable exact reply.
4. Follow the result destination and return control. Recent activity records events, not current jobs; a reply or completion is not a release.

## Finish a task without losing its evidence

Required reviews, prerequisites and evidence must satisfy this task. Handoff or synthesis alone does not close it.

1. Read the task's reason and next action. Historical Done can need current review; that alone is not failed tests or unfinished implementation.
2. Open Update task status. Distinguish the saved record from your change; choose Mark done under Task status only when offered.
3. Choose saved evidence selects saved project items or run outputs; advanced exact paths remain available.
4. Enter a Reason or completion summary, then Save task status. Inspect refusals rather than bypassing or renewing reviews. Check an uncertain original request before resending.
5. Done, review, support, adoption, integration, release and cleanup differ; a verdict is history. Unavailable output is gone; use issued reads.

## Use a workflow

A workflow is an optional reusable set of steps, such as drafting and reviewing; reading and writing need none.

1. Open Workflows. Choose a saved workflow or New workflow and read its purpose and project/workspace ownership.
2. In Design, write steps, then Check execution. Save definition records a version; unsaved edits stay local.
3. Browse saved versions pages history; Read saved version and Read next saved-body part open text; Close saved version keeps the draft and save check.
4. Runs reads recorded project-workflow uses. Use as new draft copies a saved version to a chosen owner; Prepare agent run needs it saved. Prepare external run is the CLI path.
5. Preparation is not execution; Send and start/apply stay explicit. An unsupported view does not prove no run exists.
6. To share a saved workflow, open it from Explore across projects as a Workflow Definition, then Open Handover. Prepare, inspect the manifest and export to a fresh local directory; lineage export works the same way.

## Find Help and recover

Help can explain and navigate. It never submits, approves, sends or applies work for you.

1. Open Help at the confusing decision. Read its purpose, next action/effects or a task recipe.
2. Back or Close returns to its current opener unless you deliberately moved elsewhere. Previous object, containing scope and leaving Task context have different destinations.
3. For an uncertain request, keep the original and use its Check or Inspect action; Unknown does not mean no effect.
4. Open the conversation or run for current execution; Advanced details keep exact identities.
