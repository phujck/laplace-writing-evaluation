Concrete investigations after the first-use record
-------------------------------------------------
1. Initial Now screen showed CLEANUP_UNRESOLVED for two research run indexes.
   research_runs.py::_inspect_pending_index (around line 473) treats an existing
   run directory without index.json as unresolved. Both bundled run directories
   lack that index. This explains the warning; it does not show a new running job.

2. Historical execution availability refuses relocation.
   research_runs.py::_result_target (around line 197) requires recorded relative
   and absolute result coordinates to identify the same file in the selected
   Research home. The bundled fixture job's result_absolute/producer_base/cwd
   still name the original host checkout. The owner refuses that mismatch.
   I read only the copied metadata strings, never their original targets.

3. Source-reference placeholders have a packaging explanation.
   manuscript/walk.py (around 2659) reads built .bbl/.aux files for citations and
   references. None are distributed. The PDFs contain typeset numbering, whereas
   a fresh source projection cannot recover it from absent auxiliary files.
   This is a reader limitation, not evidence that the supplied PDF lacks references.

4. Missing diagram source and unbound Loss Geometries records are confirmed by
   the selected registry paths, manuscript_spec.json and local file existence.
   The manifest checker passes because it checks selected listed bytes, not all
   possible dependencies or application bindings.
