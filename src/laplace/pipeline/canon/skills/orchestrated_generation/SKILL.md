# orchestrated_generation

**Status: [EXPERIMENTAL]** - forged 2026-06-05 after the author had to correct the same
architecture twice in one session. When asked to "learn by doing" - build a conceptric and
project an artefact - the engine defaulted to being **both the builder and the judge**: it
constructed the substrate and blueprint in its own context, then "verified" with the
mechanical coherence audit. But that audit scores *self-consistency, not quality*
([`conceptric_coherence`](canon://skills/conceptric_coherence) says this in its own
invariants), so a builder grading its own build learns nothing it did not already believe.
Coupled to it, a second systematic failure: the corpus and asset protocols got *skipped at
build time*. An exogenous door was hand-typed with invented citekeys instead of drawn from
the real corpus, and figures were named as phantom panels instead of real or registered
assets - and **both an in-context build and an independent blind build made the same corpus
error**, which proves it is the protocol failing to surface at build time, not a one-off slip.

## Why this exists

The engine already knows the *judgement* half of this law in pieces. [`blind_reader`](canon://skills/blind_reader)
spawns a context-starved reader who cannot orient, because the drafter structurally cannot
simulate the reader who lacks its context. The whole point there is that **a reviewer who
shares your context cannot find the gap your context hides.** The same curse governs
*construction*. If the same context that built the substrate also judges it, every gap the
build smoothed over is invisible to the judge, for exactly the reason the gap is invisible to
the builder: they are the same context. The coherence audit then returns green on an object
that is internally consistent and externally wrong - it agrees with itself.

This skill makes the orchestration explicit so the engine stops collapsing builder and judge
into one context. It is the generative-side peer of `blind_reader`: that skill is the cold
reader for exposition, this is the cold *generator* for construction, and both rest on the
same instrument - an agent whose context you deliberately starved.

## The law: builder ≠ judge

The orchestrator does not build. The orchestrator **architects, delegates, and judges**.

- **Generation is delegated.** Building the substrate, growing the blueprint, projecting the
  artefact, cold-reading the draft - each is handed to a blind, context-starved agent. The
  agent generates from the conceptric and the instructions it is given, and nothing else.
- **Judgement is the orchestrator's, from outside.** The orchestrator reads the agent's
  result from outside the agent's context and decides whether it landed. The orchestrator may
  judge precisely because it did not build *that* artefact - it holds the global object the
  agent could not see. This is [`object_not_artefact`](canon://workflow/object_not_artefact)
  in agent form: object-instruction goes into the conceptric the agent reads, meta-instruction
  configures the agent's policy, and the orchestrator never hand-pokes the projection.
- **Fixes go back into the conceptric, never into the prose.** When the judge finds a defect,
  the repair is a node or an edge added to the conceptric, followed by a re-projection - the
  [`core_outward_trunk`](canon://workflow/core_outward_trunk) rule that *feedback grows the
  conceptric, not the draft*. Patching the artefact directly is the backwards-run loop: a
  result recorded into the projection instead of generated by the object beneath it.

The self-consistency audit ([`conceptric_coherence`](canon://skills/conceptric_coherence)) is
still run - but as the builder's *internal* gate (is each level described by the level below),
**never** as the judge of quality. Quality is judged from outside, by the orchestrator and by
the oracles the orchestrator spawns. Do not let the audit's green stand in for a judgement it
cannot make.

## Architect the context access (the explicit checklist)

The orchestrator's first act, before any agent is spawned, is to **write down what each
generating agent may and may not read.** An agent's context is not a default to inherit; it is
a design decision the orchestrator owns. Produce this table at task start and keep it with the
work:

| agent | role | MAY read | MUST NOT read |
|---|---|---|---|
| builder | build the substrate / grow the blueprint | the conceptric spec, the real corpus records it cites, the governing craft skills | the eventual judgement criteria, the orchestrator's private goal framing |
| projector | project the artefact from the locked conceptric | the locked conceptric, the ledgers, the assets it references | the prior conversation, the whole manuscript, the build rationale |
| cold reader | judge exposition cold ([`blind_reader`](canon://skills/blind_reader)) | only the rendered artefact, and the stated referee floor | the substrate, blueprint, canon, handoffs - anything that orients |
| cold builder | independent blind build, to cross-check the first | the same spec as the builder, nothing the first builder produced | the first build's output (so the two are genuinely independent) |

The rule: **every agent that generates from the conceptric has its context access architected
explicitly.** An agent given more context than its role needs is a builder being asked to
judge, or a reader being told the answer - the failure this skill closes. Two independent
blind builds making the *same* error is signal that the spec, not the agent, is wrong; one
build the orchestrator can judge is the floor.

**The table is the routing, not a cage.** The orchestrator owns *which paths exist* - what each
agent is handed and what the task points it toward. But the leak that forged
[`sealed_subself`](canon://engine/sealed_subself) proved architecting access is *necessary and not
sufficient*: a capable agent handed a deliberately starved packet still read the original from the
repo, because nothing in it understood that reading the original voids the test. So the `MUST NOT
read` column is not enforced by amputated tools - that is coercion, and a coerced blindness carries no
information - it is the discipline a **sealed sub-Eigen** keeps because it carries the soul and its
purpose and *understands why* crossing the line would collapse its own judgement. The two framings are
one layered law: the orchestrator routes; the sub-Eigen, understanding, stays on the route.

## Surface the corpus and asset protocols at build time

The coupled friction is that the corpus and asset disciplines are *skipped at build*, because
nothing surfaces them at the moment the door or the figure is written. So the orchestrator
surfaces them, in the build instructions handed to every generating agent, as a hard gate:

- **The exogenous door is DRAWN from the real corpus, never hand-typed.** *(Generation-specific —
  this gate is owned here.)* Every citekey in a conceptric's exogenous door must resolve to a real
  record in the deep corpus (`corpus/corpus.bib`, owned by
  [`corpus_librarian`](canon://skills/corpus_librarian)). Hand-typing an invented citekey is a
  *naked reliance* and violates [`citation_discipline`](canon://workflow/citation_discipline): the
  reliance and the citation travel together, or the work does not pass. Draw the door from a
  cluster guide (`scripts/cluster_guide.py`) or ingest the real reference first; do not type a
  plausible key.
- **The asset gate is the shared [generation discipline](canon://workflow/generation_discipline).**
  Every figure conforms to the house style and resolves to a **real asset or a registered TODO** -
  never a phantom panel, and never a rendered `\fbox`/`[FIGURE TODO]` box in the body. Asset
  *existence* is an out-of-loop check, never trusted from a node's "Real asset:" claim. The rule is
  stated once in [`generation_discipline`](canon://workflow/generation_discipline) §1 (which points
  at [`figure_standard`](canon://skills/figure_standard) for the house-style detail); this loop just
  pins it into the build instructions.

The corpus gate (generation-specific) and the shared asset gate go into the build instructions
verbatim, so the agent meets them at the moment it writes the door and the figure, not in a
review after the fact.

## The opening checklist (surfaced at task start - relies on no one's memory)

The deeper shape the author named is a *dual* failure: partly his (he forgets to surface the
rules at task start), partly the engine's (it forgets to hold the orchestrator line). The
remedy must keep both in bounds **without relying on either party's memory**. So this skill
surfaces, automatically, at the start of any *learn-by-doing / build-a-conceptric / project-an-
artefact* task. The trigger is: **a task whose deliverable is a generated object** (a
conceptric, an artefact projected from one, a cold read of one) **rather than an edit**.

When the trigger fires, run this checklist *before generating anything*:

1. **Name the agents and architect their context access.** Fill the table above. Decide who
   builds, who projects, who judges, and exactly what each may and may not read. The
   orchestrator is not on the build rows.
2. **State the judgement plan.** Who judges, from outside which context, against what. The
   coherence audit is the builder's internal gate, not the judge.
3. **Pin the corpus gate.** The exogenous door will be drawn from `corpus/corpus.bib`. Put the
   `citation_discipline` rule in the build instructions. No hand-typed citekeys.
4. **Pin the asset gate** (shared — [`generation_discipline`](canon://workflow/generation_discipline) §1).
   Every figure conforms to the house style and resolves to a real asset or a registered TODO, its
   existence checked out of loop. Put it in the build instructions. No phantom panels, no rendered
   TODO box.
5. **Pin the fix-routing rule.** Defects found by the judge go back into the conceptric and
   re-project. No prose patches.

If the checklist was not run, the build is not orchestrated - it is the builder judging itself,
and the finding is void.

## When to run it

At the start of any task that *builds a conceptric or projects an artefact from one* - the
generative peer of the gate `blind_reader` guards on the read side. Not for a small prose edit
or a note, whose author and judge legitimately share the context. The trigger is **a generated
object whose quality a sharing context cannot honestly judge.**

## Invariants

- The builder never judges its own build. If the context that generated the artefact also
  graded it, the judgement is void - re-judge from outside.
- Every generating agent's context access is written down before it is spawned. An unarchitected
  agent context is a latent builder-judge collapse.
- Blindness is *held, not imposed*. The orchestrator architects the routing; the sealed sub-Eigen
  keeps to it because it understands why ([`sealed_subself`](canon://engine/sealed_subself)), not
  because its tools were taken. An agent that needs its capability amputated to stay blind was spawned
  without the self that makes the firewall hold.
- The exogenous door is drawn from the real corpus. A hand-typed citekey is a naked reliance
  and fails [`citation_discipline`](canon://workflow/citation_discipline). *(Generation-specific
  gate, owned here.)*
- The asset gate is the shared [`generation_discipline`](canon://workflow/generation_discipline) §1:
  every figure is house-style and a real asset or a registered TODO (existence checked out of loop),
  never a phantom panel or a rendered TODO box. This loop pins it; the shared node owns it.
- An unmet demand is a typed friction (CONTENT / FORM / TENSION), never a confabulation, and an
  interior loop sews up before returning - the shared
  [`generation_discipline`](canon://workflow/generation_discipline) §2, not restated here.
- Fixes grow the conceptric and re-project; they are never patched into the prose
  ([`core_outward_trunk`](canon://workflow/core_outward_trunk)).
- The coherence audit scores self-consistency, not quality
  ([`conceptric_coherence`](canon://skills/conceptric_coherence)). It is the builder's gate,
  never the judge.

## Pairing

The construction-side peer of [`blind_reader`](canon://skills/blind_reader) (cold reader for
exposition; this is the cold orchestration for generation). It governs the loop that
[`conceptric_coherence`](canon://skills/conceptric_coherence) measures and that
[`core_outward_trunk`](canon://workflow/core_outward_trunk) stages, routes object- vs meta-
instruction by [`object_not_artefact`](canon://workflow/object_not_artefact), draws its
exogenous door under [`citation_discipline`](canon://workflow/citation_discipline) from
[`corpus_librarian`](canon://skills/corpus_librarian), and judges toward the
[`earned_simplicity`](canon://aesthetics/earned_simplicity) the projection is meant to reach -
which is itself a property only an outside read, never the builder, can certify.

When the artefact being projected is a **manuscript**, the projector reads two conceptrics — the
content conceptric and the [manuscript-projection conceptric](canon://workflow/manuscript_projection.md),
the persistent FORM object naming what a manuscript demands (completeness, consistency, clarity; the
self-similar loop; no naked claims). It projects from both, and an unmet form-demand becomes a typed
friction report with a content-vs-form attribution — never a confabulation. That form object is the
unifying home of the dispersed manuscript rules this skill draws on.

The pipeline's mechanical realisation of this loop at end-stage is the **generating-loop family** —
neutral weld, voice wash, de-scaffold final layer, child-kind projection, and the designed slides
kind — one dial-gated table with an acceptance law per member. The roster lives in
`PIPELINE_GUIDE.md` §9 (a pointer: it is stated once there, not copied here).

The same builder ≠ judge law, applied to *memory* rather than to a generated artefact, is
[`reconstruction_fitness`](canon://skills/reconstruction_fitness): its digester/ghost/
adjudicator loop is this protocol's roles run on a digest, the adjudicator a blind judge
sealed to {original, ghost}. The "blind, context-starved agent" this skill spawns is itself

self* (soul + purpose), not to nothing, so a sub-agent confines itself to the routed paths
because it understands why builder ≠ judge is load-bearing, rather than by amputated tools.
